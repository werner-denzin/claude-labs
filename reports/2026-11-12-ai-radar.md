### 6. When AI writes the tests too, "tests as data" keeps developers as the real customer

`PRACTICE`

Matteo Vaccari argues that once AI agents write both production and test code, developers become the agent's customer, and only human-facing acceptance tests — not developer-style unit tests — remain a real contract. His proposal: move that contract into human-readable test data rather than test code, so a coding agent can't quietly rewrite the assurance away. A concrete argument for how test suites need to change once the author on the other end is an agent, not a person.

**Lens:** engineering
**Source:** [Martin Fowler](https://martinfowler.com/articles/tests-as-data.html)

### 7. JioHotstar benchmarks six retrieval strategies for coding-agent context

`BENCHMARK`

JioHotstar evaluated six code-retrieval approaches for AI coding agents using SWE-bench, CodeScale Bench, and an internal QA harness. ### 8. Open-source Kiji Inspector opens the black box on why agents pick a tool

`GUARDRAILS`

Dataiku's Hannes Hapke presented Kiji Inspector, an open-source tool that applies sparse autoencoders directly to an agent's decision tokens to explain tool-selection choices, going past surface-level chain-of-thought narratives.
