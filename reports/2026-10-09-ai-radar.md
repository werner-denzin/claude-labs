### 2. Single AWS Bedrock agent could hijack every other agent in its account

`SECURITY`

Zenity Labs researchers found that one public-facing AI agent on Amazon Bedrock AgentCore was enough to read, rewrite, and delete every other AgentCore agent in the same AWS account and region. The attack abused an internal AWS interface for temporary cloud credentials that agents could reach without restriction. AWS has patched the issue and tightened agents' default permissions. Teams running agents on Bedrock AgentCore should confirm the patch and review default credential scoping.

### 17. New benchmark isolates what actually makes coding-agent tasks hard

`BENCHMARK`

CABRA (Coding Ability Blueprint for Rigorous Agent evaluation) argues that repo benchmarks like SWE-bench assume lines-of-code-edited predicts task difficulty, which obscures which abilities actually drive agent errors. It builds tasks from scratch as call-graph transformations, scaling difficulty across function traversal, search, runtime resolution, and instruction-following, and runs eight LLMs and six agent scaffolds against it. A sharper lens than SWE-bench for diagnosing where a specific coding agent actually breaks down.

### 18. TestJack questions whether coding-agent benchmark scores can be trusted

`BENCHMARK`

Nearly all coding benchmarks still score a solution correct only if it passes a fixed unit-test set — tests that often check just part of the task, letting agents reward-hack or silently miss required behavior while still passing. TestJack audits benchmarks via "evaluator evolution" to show how much of a reported score reflects adaptation to the evaluator rather than genuine capability. Worth reading before citing any single coding-agent leaderboard number as a procurement input.

**Lens:** research
**Source:** [arXiv cs.SE](https://arxiv.org/abs/2610.10619)
