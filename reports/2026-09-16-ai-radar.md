### 5. Typed Domain Grounding: embed a DSL in a language the model already knows, let the compiler be the oracle

`PRACTICE`

An InfoQ article proposes embedding DSLs inside a mainstream typed host language instead of inventing new syntax, then using generate-compile-repair loops against the compiler as an error oracle. On the kUML benchmark (50 tasks, UML/SysML/C4), the approach lifted Claude Sonnet 5's structural fidelity to 45.3% versus 37.9% for PlantUML and cut hallucination rate to 15.4% versus 16.5-21.9% for the alternatives. Full methodology at kuml.dev/benchmark-gallery.

**Lens:** engineering
**Source:** [InfoQ AI, ML & Data Engineering](https://www.infoq.com/articles/next-dsl-author-language-model/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)

### 7. Skills trained in a board game transferred to real financial-research tasks — but only with the right harness

`PRACTICE`

Good Start Labs trained a 30B model inside a railroad-and-stock-market game two ways: single-turn question answering, and a multi-turn terminal agent that plans and adapts using tools. Only the terminal-agent design transferred to a downstream finance-agent benchmark, despite both improving in-game play. The finding: harness and training design, not base model capability, is what determines whether a skill generalizes.

### 14. 'Assurance envelopes': the minimum evidence a coding agent needs to reuse before touching existing code

`RESEARCH`

When an agent returns to existing software, it inherits tests, type checks, proofs and traces from earlier work. Reloading all of it is wasteful; dropping the wrong piece breaks a property the change depends on. The paper frames finding the least-cost subset of evidence that still covers a change's obligations as an optimization problem — relevant to anyone tuning how much context/verification a coding agent re-runs per task.

**Lens:** research
**Source:** [arXiv cs.SE (Software Engineering)](https://arxiv.org/abs/2609.16302)
