### 3. Simon Willison: telling Fable 5.2 "this codebase is yours" changes how it edits code

`PROMPT ENGINEERING`

In hands-on testing, Fable 5.2's behavior on small coding tasks tracked how the prompt framed code ownership. Told nothing, or told the code belonged to someone else, it tended to bolt on new structure and repeat existing code. Told the codebase was its own to improve, it merged duplication and cleaned up structure instead. A one-line ownership framing in a system prompt is a cheap lever worth testing on real Claude Code tasks.

### 7. Benchmark of six LLM reliability layers: voting and self-correction don't fix errors, they just withhold answers

`BENCHMARK`

A benchmark of six reliability/verification layers found that voting and self-correction don't recover accuracy — they only flag doubtful outputs as low-confidence, trading yield for safety. The authors argue production systems gain more by replacing generation with deterministic lookups where possible, tracking yield alongside raw accuracy, and fixing extraction bottlenecks before stacking more verification on top.

### 8. Sourcegraph built a PR-routing bot that triages reviews as Ship, Show or Ask as agents write more code

`CODE REVIEW`

As coding agents produce more code, routine approval-chasing became Sourcegraph's review bottleneck. Their bot has a coding agent read the diff and the author's recent contribution history, then recommends Ship (no review), Show (review after merge) or Ask (review before merge) via GitHub Actions. It launched in recommendation-only mode before enabling approvals, and sensitive changes — auth, data exposure — always require review regardless of author history. Result so far is qualitative: fewer requests for a quick stamp.
