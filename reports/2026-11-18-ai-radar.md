### 6. Simon Willison: run coding agents against external sandboxes, not the host

`HARNESS`

Willison argues the agent itself should run outside the sandbox while any code it executes stays inside a separate one, so a mistake or prompt injection can't touch the host machine. He and collaborators released three sandbox servers — built on v86, Apple Containers, and Microsoft's Quicksand — sharing one localhost API that Pi, Claude Code, or Codex can target. An optional allow-list proxy restricts which hosts the sandboxed code can reach, and credential replacement lets the agent make authenticated calls without ever holding the secret.

### 13. Telling a coding agent its token budget does nothing; enforcing the cap does

`RESEARCH`

A factorial experiment (5,835 runs, two open models, three cap levels, two program-repair benchmarks) crossed enforcing a token cap against telling the agent about it, with a placebo sentence as control. Enforcing a cap cut resolution by 20 points but cut tokens-per-resolved-task roughly twelvefold. Telling the agent its budget changed nothing beyond the placebo — which itself raised resolution 7.2 points over silent enforcement, a framing effect the authors don't fully explain.

**Lens:** research
**Source:** [arXiv cs.SE (Software Engineering)](https://arxiv.org/abs/2611.21614)

### 14. A coding-agent context bug: mixing file, symbol, and index state from different revisions

`RESEARCH`

Agents querying a repo mid-edit can get a response built from the source, symbol graph, and retrieval index at different revisions — "mixed-revision code context" — which produced two unsafe responses in 150 update trials on the Gin project. The fix is a publish contract: before a cutover point the service waits, reports unavailable, or serves the full old revision; after it, only the full new revision, tagged with one shared version ID across every view. With that contract, unsafe responses dropped to zero, and a journaled, idempotent publish step recovered cleanly from interrupted updates.

**Lens:** research
**Source:** [arXiv cs.SE (Software Engineering)](https://arxiv.org/abs/2611.21616)
