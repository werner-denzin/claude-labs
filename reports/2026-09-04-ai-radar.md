## 🟠 Medium

### 3. LangChain rebuilds MCP support on a stateless protocol, adds elicitation via LangGraph interrupts

`MCP`

LangChain moved MCP out of the separate langchain-mcp-adapters package into langchain.mcp, built on FastMCP. The new MCP spec drops session-based connections entirely, so a server redeploy no longer kills live sessions and tool catalogs can be cached instead of re-fetched. Elicitation -- human-in-the-loop approval mid-tool-call -- now surfaces as an ordinary LangGraph interrupt instead of holding a connection open.

**Lens:** engineering
**Source:** [LangChain Blog](https://www.langchain.com/blog/mcp-in-langchain-stateless-protocol-elicitation-and-more)

### 5. Shopify compresses a 6,000-token system prompt to 1,500 with "gisting", cuts agent latency 38%

`Context engineering`

Shopify trains learned "gist" tokens that reproduce a full system prompt's behavior at a quarter of the length, applied to its Sidekick GraphQL agent: time-to-first-token dropped from 438ms to 354ms, end-to-end latency from 6.8s to 4.2s, throughput up from 20.2 to 23.4 queries/sec. ### 9. Requirements keep changing mid-session in real coding-agent use, not just in benchmarks

`Research`

Mining real-world coding-agent sessions rather than curated benchmarks, the authors find agents routinely implement changes before users have fully articulated what they want -- echoing a known requirements-engineering pattern where stakeholders can't state a constraint until something exists to react to. Curated benchmarks that fix requirements upfront miss this rework entirely, which the paper argues undercounts how much of an agent's real cost is spent re-doing work.

### 11. A taxonomy separates "code hallucination" from ordinary bugs, with a benchmark to measure it

`Research`

Code that imports nonexistent packages or claims to implement algorithms that violate proven theorems, while still compiling and running, is a distinct failure mode from an ordinary bug in otherwise-grounded code, the authors argue. They propose a three-dimension taxonomy and a benchmark for it -- useful groundwork for anyone building automated review or eval gates that currently only check for bugs, not for this kind of confident fabrication.

**Lens:** research
**Source:** [arXiv cs.SE (Software Engineering)](https://arxiv.org/abs/2609.03267)
